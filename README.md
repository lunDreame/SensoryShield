# SensoryShield

SensoryShield는 nRF54LM20 DK 기반의 로컬 감각 환경 제어 펌웨어입니다. Zephyr RTOS와 C++17을 사용하며, 로컬 센서 처리, WS2812B LED 링 및 PWM 팬 제어, 영구 앱 설정, Thread IPv6 네트워크, 로컬 HTTP REST API를 포함합니다.

## 펌웨어

펌웨어는 NCS sysbuild 기준으로 빌드합니다. MCUboot, Matter factory data, SensoryShield 애플리케이션이 함께 빌드되고, 전체 플래시 때 같은 순서로 보드에 기록됩니다.

처음 빌드하거나 빌드 설정이 바뀐 경우:

```sh
./scripts/build.sh --pristine
./scripts/flash.sh
```

평소 증분 빌드와 앱만 빠르게 다시 올리는 경우:

```sh
./scripts/build.sh
./scripts/flash.sh --app-only
```

`./scripts/flash.sh`는 `mcuboot`, `matter_factory_data`, `SensoryShield` 도메인을 모두 플래시합니다. `./scripts/flash.sh --app-only`는 이미 MCUboot와 factory data가 설치되어 있다는 전제에서 SensoryShield 앱 도메인만 업데이트합니다.

VS Code 작업도 같은 스크립트를 호출하도록 구성되어 있습니다.

## 프론트엔드

```sh
cd frontend
npm install
npm run dev
npm run build
```

펌웨어 빌드는 프론트엔드 production 빌드를 실행하고, 생성된 HTML, JavaScript, CSS를 압축해 펌웨어 이미지에 포함합니다. 보드에서는 Thread 네트워크에 붙은 뒤 로그에 출력되는 LAN-routable IPv6 주소로 웹 UI를 제공합니다.

개발 서버는 5173 포트에서 실행됩니다. 실제 보드로 `/api` 요청을 프록시하려면 `frontend/.env`에 `API_TARGET=http://[보드 IPv6 주소]`를 설정하거나 `API_TARGET='http://[보드 IPv6 주소]' npm run dev`처럼 대상 주소를 지정합니다. 보드가 없으면 프론트엔드는 오프라인 미리보기 상태로 동작하고 장치 제어는 비활성화됩니다.

REST API는 `/api/status`, `/api/light`, `/api/fan`, `/api/mode`, `/api/profile`, `/api/diagnostics`, `/api/factory-reset`을 제공합니다. `/api/light`는 `power`, `brightness`, `cct`, `rgbMode`, `red`, `green`, `blue`를 받을 수 있습니다. Matter ColorControl은 Level, ColorTemperature, Hue/Saturation 명령을 지원합니다. factory reset 엔드포인트는 확인 요청이 있는 경우에만 동작합니다.

`/api/diagnostics`의 `fan`은 정규화된 목표 PWM, 마지막 성공 duty, 부스트/유효/오류 상태,
마지막 성공 변경 후 경과 시간, 팬 안정화 대기와 전체 제어 입력 안정 상태를 구분해 보고합니다.
PWM은 전기적 구동 명령이며 RPM·회전·풍량 측정값이 아닙니다. 오류 상태의 마지막 성공 duty도 현재
물리 출력을 보장하지 않습니다. 실제 장비에서는 **OFF → 기동 부스트 → 목표 PWM → 안정화 대기 → 정상 판정**
순서와, PWM 실패 시 출력 무효 및 학습 보류를 로그와 진단 화면에서 확인합니다.

## 현재 하드웨어 매핑

- BH1750 I2C: SDA `P1.12`, SCL `P1.13`
- MP34DT01 PDM: CLK `P1.14`, DATA `P1.11`; 16 kHz mono, 100 ms window
- HC-SR501 PIR: `P1.10`
- WS2812B 12 LED ring: `DI` -> `P3.00` 출력 가능 GPIO 패드, `5V` -> 5 V 전원, `GND` -> 공통 GND, `DO` -> 다음 LED 체인 연결용 또는 미사용
- Fan PWM: `P3.02`

팬의 0%가 아닌 요청은 보호자 상한을 먼저 적용합니다. 상한이 1~17%이면 팬을 구동하지 않고,
상한이 18% 이상이면 1~17% 요청을 최소 구동 duty 18%로 적용합니다. 정지 상태에서 시작할 때의
100%/350 ms PWM은 팬 기동을 위한 일시적 부스트라서 보호자 정상 출력 상한보다 높을 수 있습니다.
이는 PWM 명령이 성공했다는 뜻이며 실제 회전, RPM, 풍량 또는 공기질 개선을 확인했다는 뜻은 아닙니다.

WS2812B `DI`는 보드의 출력 가능한 GPIO 패드에 연결합니다. 현재 펌웨어는 `P3.00`을 WS2812B 데이터 파형 출력으로 사용합니다.

WS2812B 조명은 밝기 디밍, RGB 색상, 백색 색온도 제어를 지원합니다.

Thread REST 접속에는 보더 라우터가 LAN으로 광고한 OMR IPv6 주소를 사용합니다. 링크 로컬, mesh-local, RLOC 주소는 일반 LAN 클라이언트에서 직접 접근할 수 없습니다.

### 처음 설정과 자동 학습

처음 설문조사는 빛 민감도, 소리 민감도, 자극 완화 시 사용할 색온도 세 질문입니다. 별도의 환경 측정·조명/팬 체험 단계는 없습니다. 민감도는 변화에 반응하는 크기에 반영하며 반응 시간을 직접 정하지 않습니다. 선택한 색온도는 조명을 낮출 때 사용할 목표입니다. 250/333/417 mired 프리셋은 제품 선택값이며 치료 기준이 아닙니다. 설정 화면에서 나중에 변경할 수 있습니다.

자동 학습은 평소 대비 밝기·소리 증가를 비교하기 위한 것입니다. 첫 유효 자료부터 임시 중앙값으로 점수를 계산하며, 각 채널에 수락한 새 표본 31개가 쌓이면 전체 창을 사용합니다. 알고리즘 주기 250 ms에서 모두 유효하고 출력이 안정적이면 약 8초입니다. 출력 전환·오류·중복 자료는 세지 않아 실제 시간은 길어질 수 있습니다. 이는 초기 통계 창의 준비이며 시간대별 개인화 완료나 임상적으로 검증한 적응 기간이 아닙니다. 재부팅 때에는 현재 환경으로 다시 시작합니다. `sensor.baselineReady`는 입력과 통계 창의 준비 상태로 정확도 백분율이 아닙니다.

화면에는 “평소 환경을 자동으로 학습하고, 빛과 소리 변화에 맞춰 조명과 팬을 조절해요.”라고 안내합니다. 점수는 주변 변화 지표이며 아이의 불편함을 확정하거나 진단하지 않습니다. 표시 범위는 `STIMULUS_MAX_SCORE = 4`, 문구 경계는 1.4·2.8입니다. 점수는 증가 방향만 계산합니다. 학습은 갱신 전 중앙값 대비 절대 변화/MAD에 각 민감도를 곱한 합이 0.7 이하인 작은 변화만 수락합니다. 0.7 초과·1.4 미만은 학습과 완화를 모두 보류하는 관찰 구간입니다. 기본 민감도100→102 lx는 학습하고100→103 lx는 학습하지 않습니다. 큰 감소도 학습에서 제외해 원래 환경 복원 시 오판을 막습니다. 첫 표본 이후부터 이 조건을 적용하며, AUTO의 평소 출력이 안정된 동안에만 학습합니다. MANUAL/OVERRIDE/SAFE, 완화·복귀 및 출력 전환 중에는 기준을 고정하되 현재 센서 점수는 계속 계산합니다.

### 자동 모드 기본 출력과 자극 완화

저장 호환성을 위해 API 필드 이름 `preferredBrightness`, `preferredFanPercent`는 유지하되 설정 화면에서는 평소 조명 밝기와 평소 바람 세기로 설명합니다. 설문에서 두 값을 수집하지 않고 보호자가 설정에서 허용 범위 안으로 직접 조절합니다. 정상 조명의 색온도는 `normalCCTMireds`로 별도 설정합니다(기본250 mired). 기존 설정을 복원할 때는 과거 동작을 보존해 `minCCTMireds`를 상속합니다. `preferredCCTMireds`는 자극 완화 시 사용할 빛입니다. 색온도 선택이 평소 밝기·바람 세기를 덮어쓰지 않습니다.

자동 조명은 정상 → 자극 확인 → 완화 유지 → 회복 확인 → 점진 복귀 순서입니다. 유효하고 출력이 안정된 입력에서 점수 1.4 이상이 750 ms 지속되면 밝기를 낮추고 선택한 완화 색온도를 적용합니다. 첫 진입점에서는 정상 밝기에서 최대 2%p만 낮추며, 점수가 4에 가까워질수록 설정 하한까지 감소 폭을 늘립니다. 완화 중에도 현재보다 더 큰 감소가 필요한 상태를 새로750 ms 확인한 뒤 추가로 낮춥니다. 확인 구간 전체에서 유지된 감소 폭만 채택하므로 마지막 한 번의 큰 값으로 하한까지 내려가지 않습니다. 추가 감소 후 최소 유지 시간을 다시 셉니다. 밝기와 색온도 목표는 함께 전달되고 기존 구동 루프가25 ms마다 밝기 최대2%p·색온도 최대8 mired씩 동시에 전환합니다. 완화 중 색온도를 새로 저장하면 밝기가 이미 하한이어도 새 색온도로 전환하며, 전환 전 측정값으로 곧바로 복귀하지 않도록 유지·회복 확인을 다시 시작합니다. 최소 유지 시간(기본1,500 ms) 후 점수0.7 이하가 복귀 확인 시간(기본2,500 ms) 동안 지속되면 복귀합니다. 유효하고 안정된 입력에서 500 ms마다 밝기를 2%p 올리고 실제 완화 시작점의 색온도에서 정상 색온도로 점진 복귀합니다. 복귀 중 0.7 초과·1.4 미만이면 밝기·톤을 유지하며, 다시 낮아져도 복귀 확인 시간을 새로 충족해야 합니다. 1.4 이상이 750 ms 지속되면 마지막 안전 출력으로 되돌아가 추가 복귀를 차단합니다. 이후 같은 안정 출력에서 조도2 lx 또는 RMS0.0025 이상의 추가 감소를 관측하면 다시 낮은 변화 확인을 시작할 수 있습니다. 이 폭은 기존 측정 floor를 사용한 공학 조건이며 임상 기준이 아닙니다. 평소 출력까지 강제 복귀하거나 시간만으로 실패한 복귀를 반복하지 않습니다. 출력 전환 중에는 안정화를 기다리고 센서 오류를 회복으로 취급하지 않습니다.

위 점수·시간·변화 폭은 반복 제어를 막기 위한 초기 공학 설정이며 임상 기준이나 논문이 검증한 값이 아닙니다. 실제 센서 지연·출력 반응에 맞춰 검증하고 조정해야 합니다. MANUAL/OVERRIDE와 직접 설정한 계속 유지 기능을 우선하며, 모드 변경 때 조명·팬 완화 상태를 다시 시작하고 학습 기준은 보존합니다. 재실 자동화가 켜져 있으면 유지 시간 경과 시 종료하고 움직임이 재감지되면 자동 제어를 재개합니다. 끄면 미감지로 종료하지 않습니다.

팬은 조명에도 입력되는 공통 소음 점수 `StimulusScorer.sound`를 사용합니다. 팬 별도 중앙값/MAD·학습·peak 기반 제외 조건은 제거했습니다. 첫 유효 평소 자료로 만든 임시 기준부터 반응하며 전체 창 준비 상태를 제어 금지 조건으로 사용하지 않습니다. 정상 출력은 `preferredFanPercent`(기본60%), 조용 출력은 `reliefFanPercent`(기본20%)와 정상 출력 중 작은 값입니다. 정상 출력0%이면 자동 팬을 끕니다. 소음 단독에서는 조명·팬이 동일한 1.4/0.7 문턱과 확인 시간을 사용합니다. 조명은 빛+소리, 팬은 소리만 판단해 빛 단독 변화는 팬을 낮추지 않습니다. 완화 목표는 서서히 낮추고, 복귀 중 중간 점수에서는 현재 속도를 유지합니다. 높은 점수가 다시 확인되면 마지막 안전 속도로 되돌린 뒤 같은 출력에서 RMS0.0025 이상의 추가 감소가 확인될 때까지 재시도를 막습니다. 초기 정상 출력·입력 처리·공통 소음 판단 변경을 소음·환기 담당자에게 공유해야 합니다.

### 기본 조명 출력 변경 시 비교 기준 갱신

보호자가 설정에서 기본 밝기나 기본 색온도를 저장해 실제 기본 출력이 달라지면 빛 기준 갱신을 예약합니다. 출력 상한 변경으로 기본 출력이 달라지는 경우도 포함합니다. 수동·잠시 사용 모드, 재실 자동 종료, 센서 오류·출력 전환 중에는 기존 기준을 보존하고 예약을 기다립니다. AUTO에서 새 기본 조명과 기본 팬 출력이 실제로 관측되고 정상 제어 상태·유효하고 새로운 입력·500 ms 출력 안정화 조건을 만족하면, 그때의 lux 한 개로 **빛 기준만** 다시 시작합니다. 동일 표본은 두 번 추가하지 않으며 이후에는0.7 이하 학습 제한과31개 이동 창을 다시 적용합니다. 소리 기준과 준비 상태는 지우지 않습니다.

예약 중 AUTO에서는 이전 출력의 lux 기준을 새 출력과 비교해 다시 완화하는 순환을 막기 위해 빛 점수 기여를 잠시 보류하고 `baselineReady=false`로 보고합니다. 소음 점수와 그에 따른 조명·팬 완화는 계속 적용합니다. 이전 기본 출력에서 복귀 실패로 걸린 조명 재시도 차단은 해제하되 진행 중인 완화와 최소 유지 시간은 보존합니다. 이는 보호자의 명시적 기본 출력 변경에 한정된 기준 갱신이며, 오래 사용한 수동 출력이나 자동 완화를 학습하는 경로가 아닙니다. 새 출력을 설정한 환경 자체가 편안하다는 판정이나 원인 분리 보정을 의미하지 않습니다.

### 보호자 설정의 다섯 카테고리

개인 맞춤 기준 → 자동 반응 민감도 → 자극 완화 범위 → 자동 모드 기본 출력 → 재실 확인 설정 순서입니다. 완화에서는 밝기 하한, 완화 색온도, 팬 목표 세기, 최소 유지 시간과 복귀 확인 시간을 정합니다. 자동 모드 기본 출력에서는 밝기·색온도·팬 세기를 별도로 정합니다. 전체 출력 상한과 허용 색온도는 완화 카드 안의 펼침 항목에서 관리하며 평소 출력에도 적용합니다. 자동 조명은 백색 색온도로 제어하며 RGB는 기존 홈의 수동 제어를 사용합니다.

`reliefFanPercent`는0(끄기) 또는18~100%, `reliefHoldMs`는0~600000 ms, `recoverConfirmMs`는250~60000 ms를 허용합니다. 이 범위는 제품 입력 제한이며 임상 범위가 아닙니다. 조명과 팬 모두 최소 유지 이후 낮은 변화를 확인하고 복귀합니다. 큰 자극이 남으면 시간이 지나도 복귀하지 않습니다. 평소 팬이 완화 목표보다 낮으면 팬을 높이지 않습니다. 이 필드와 `normalCCTMireds`는 프로필API·진단API·저장·복원·자동제어·개발용모의API에 연결합니다. 이전 클라이언트가 새 필드를 생략하면 기존 저장값을 보존합니다. 재실 자동화 설정은 아래 동작을 따릅니다.

### 재실 자동화

설정의 `occupancyAutomationEnabled`는 기본 켜짐입니다. AUTO에서 마지막 움직임 후 `occupancyTimeoutMs`(기본30초)가 지나면 조명·팬을 끄고, 움직임이 다시 감지되면 저장한 평소 출력과 현재 센서 상태에 맞춰 자동 제어를 재개합니다. 움직임이 반복 감지되면 마지막 감지 시점부터 시간을 다시 셉니다. 끄면 PIR의 움직임 미감지나 오류만으로 출력을 종료하지 않고 자동 제어를 계속합니다. PIR 감지와 화면·Matter 상태 보고는 그대로 작동합니다. 직접 끄기 등으로 MANUAL이 된 출력은 움직임이 감지돼도 자동으로 켜지지 않습니다. 정상/완화 출력0%와 센서 오류 처리는 각 설정·정책을 따릅니다.

재실 자동화를 꺼도 유지 시간은 저장하며 화면에서 입력만 비활성화합니다. 재시작 후 켜기·끄기를 복원하고 v4~v8은 기존 동작과 같은 켜짐으로 이관합니다. 이전 API 클라이언트가 새 항목을 생략하면 저장된 선택을 유지합니다.

### 현재 환경 판단과 학습 제외

센서 자료에는 읽을 당시의 실제 조명 밝기·색온도·RGB·전원, 팬 속도·전원과 시각을 함께 담습니다. Matter에서 변경한 실제 출력도 포함합니다. `OutputAwareInputs`는 현재 측정된 전체 lux와 RMS를 그대로 점수 계산에 전달합니다. 자체 출력을 빼서 외부 환경을 재구성하지 않습니다. 조명·팬 전환, 읽는 중 출력 변경, 중복/오래된 자료와 오류가 있으면 학습 및 상태 전환 확인을 보류하고, 실제 출력이 안정된 뒤 최소500 ms를 기다립니다. 완화로 낮아진 측정값도 완화 결과로 판단하되 그 값을 평소 기준에 학습하지 않습니다.

자동 학습은 AUTO 평소 출력에서만 수행하며, 보호자·아이의 수동 제어와 완화·복귀 중에는 전체 기준을 유지합니다. 복귀 실패 후에는 같은 출력에서 추가 개선이 확인될 때 재시도하므로 자체 출력 감소만으로 복귀를 반복하지 않습니다. 출력 안정화 중 외부 변화가 발생하면 안정화 이후의 실제 값을 판단하지만, 실패 복귀 뒤 추가 개선의 최초 관측 시점을 놓칠 수 있습니다. 이때 더 개선되지 않으면 출력 유지가 계속될 수 있고 수동→AUTO 전환으로 상태를 새로 시작할 수 있습니다. 원인 정밀 분리와 강제 원상복귀를 보장하는 구조는 아닙니다.

`src/common/algorithm/light_sensor_calibration.h`는 설치별 광학 영향 조사에 사용할 수 있는 진단용 근사 도구로 남겨 둡니다. 현재 AUTO 경로에는 연결하지 않으며 보정 계수를 넣는 것만으로 제어가 바뀌지 않습니다. MVP의 필수 보정 절차로 두지 않습니다. 실제 배치에서는 출력별 lux/RMS와 안정화 시간, 복귀 시 반복 여부를 우선 확인합니다. 원인 분리가 필요해질 때 OFF 대비 출력 기여 및 선형 모델 오차를 조사하고 별도 통합·검증합니다.

프로필 저장 포맷은 v9입니다. v4/v5/v6/v7/v8 설정과 이전 초기 관측 기록의 저장 위치를 읽어 복원하며, 기존 평소 출력·완화 빛·민감도는 보존합니다. 추가 필드는 기존 동작에 맞는 기본값을 상속합니다. 기존 초기 관측 기록은 저장 호환성을 위해 보존하지만, 출력 상태 정보가 없어 자동 시작·재부팅 학습의 고정 시작값으로 사용하지 않습니다. `useMeasuredEnvironment: true`인 프로필 저장은 거절합니다. 기존 `/api/environment-measurement` 수집 엔드포인트는 진단용 호환 코드로 남아 있으며 사용자 설문 흐름에서 호출하지 않습니다. 공장 초기화는 기존 설정과 기록을 지웁니다. WS2812B 백색 혼합의 발광색과 센서 배치는 실제 보드에서 확인해야 합니다.

### 아이 화면의 불편 요청

아이 화면은 `너무 밝아요`, `너무 어두워요`, `너무 시끄러워요`, `너무 조용해요` 네 요청만 제공합니다. `지금 좋아요`와 시간 선택은 제거합니다. 버튼을 누르면 최신 기기 출력과 보호자 설정을 다시 읽어 실제 REST 제어 명령을 보냅니다. 밝기 요청은 현재 밝기에서 10%p 낮추거나 높이고 허용 범위를 적용합니다. 소음 요청은 조명을 낮추고 팬을 20%p 줄입니다. 팬의 최소 구동값 18%보다 낮아질 때에는 끕니다. 조용함 요청은 조명은 유지하고 팬을 켜거나 20%p 올리며 보호자의 최대 세기를 넘지 않습니다. 이는 팬 구동 요청이며 백색소음이나 치료 효과를 보장하는 기능이 아닙니다. 조명이 이미 꺼져 있을 때 밝기·소음 완화 요청이 조명을 켜지 않으며, 감소 요청이 기존 낮은 출력을 높이지 않습니다. 최대 세기가 0인 팬은 아이 요청으로 켜지지 않습니다.

출력이 바뀐 요청은 기존 기본 15분 OVERRIDE로 유지한 뒤 AUTO로 돌아갑니다. 아이가 시간을 선택하지 않으며 보호자 화면에서는 기존 수동·잠시 사용·자동 전환을 사용할 수 있습니다. 조정 폭과 기본 복귀 시간은 제품 동작 값으로 임상 기준이 아닙니다. 더 바꿀 수 없으면 한계를 안내하며, 연결 실패·부분 적용·자동 복귀 설정 실패를 성공으로 표시하지 않습니다. 재실 자동화는 AUTO에 적용하며 직접 선택한 MANUAL/OVERRIDE를 우선합니다. 아이 요청으로 생기는 자체 출력 변화에도 위 입력 분리 규칙을 적용합니다.

### 기준값의 근거 검토 (2026-10-11)

기준별 값·단위·근거·한계와 후속 판단은 [검토 기록](docs/algorithm-threshold-review.json), 실제 C++ 정책의 합성 입력 결과는 [측정 기록](docs/algorithm-threshold-measurements.json)에 보관합니다. 이번 검토에서는 큰 감소의 학습 수락 편향을 수정하고 팬이 공통 소음 점수·문턱을 사용하도록 정합했습니다. 완화 확인 시간·점수 문턱은 유지하고 학습 상한은0.7으로 분리했습니다. 재실 자동화는 설정에서 선택합니다. 문턱 부근의 첫 조명 감소는 약35%p에서2%p로 줄이고, 중간 점수 유지와 실패 복귀 차단을 추가했습니다. 큰 자극을 시간이 지났다는 이유로 평소에 흡수하는 장기 적응 경로는 추가하지 않습니다.

[NICE CG170](https://www.nice.org.uk/guidance/cg170/chapter/key-priorities-for-implementation)은 아동별 빛·소리 민감성을 고려한 환경 조정을 권고합니다. [2023년 감각 환경 조정 교차 임상시험](https://jamanetwork.com/journals/jamanetworkopen/fullarticle/2805513)은 치과에서 시각·청각·촉각을 함께 조정해 일부 스트레스 지표가 감소했습니다. 이들은 개인 설정과 환경 완화의 방향을 뒷받침합니다. 우리 조명/팬 대응 공식이나 특정 시간·색온도를 직접 검증하지는 않습니다. 해당 임상시험은 음악도 사용했으므로 무음만이 항상 좋은 환경이라고 해석하지 않습니다.

[2022년 감각 측정 연구](https://www.frontiersin.org/journals/human-neuroscience/articles/10.3389/fnhum.2022.811547/full)에서는 설문·실험 역치·신경생리 측정의 일치가 제한적이었습니다. 처음 설문조사의 값은 반응 설정을 선택하는 자료입니다. 자체 세 문항으로 임상 민감도나 불편 역치를 측정했다고 설명하지 않습니다. 센서의 자동 갱신은 환경 비교 기준의 갱신이며 아이의 생리적 적응을 측정하는 과정이 아닙니다.

[NIST의 MAD 정의](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/mad.htm)는 이상치에 강한 산포 추정을 뒷받침합니다. [modified Z-score](https://itl.nist.gov/div898/handbook/eda/section3/eda35h.htm)의 0.6745와 잠재 이상치 표시값 3.5는 현재 코드와 다른 통계 단위입니다. 현재는 `max(0, 값−중앙값) / max(raw MAD, floor)`에 각 민감도 계수를 곱한 상대 변화 지표입니다. 수식에 0.6745나 문턱 3.5만 넣으면 기존 반응 기준도 달라집니다. 이는 임상 숫자로 교체할 근거가 아닙니다.

센서 시간의 직접 근거는 [ROHM BH1750 데이터시트](https://mm.digikey.com/Volume0/opasdata/d220001/medias/docus/6165/bh1750fvi-e.pdf)입니다. 현재 H-resolution은 전형 120 ms/최대 180 ms, 약 1 lx 해상도이며 200 ms 수집 주기는 이에 맞습니다. 첫 변환 완료 후 읽기가 보장되는지도 확인해야 합니다. 데이터시트의 절대 정확도 편차 ±20%를 매 표본의 무작위 잡음이나 MAD floor로 대입하지 않습니다. `SoundFeatures.energy`는 이름과 달리 정규화 PCM RMS 진폭입니다. SPL 교정과 주파수 가중이 없으므로 논문의 dB/dBA 기준을 이 값에 그대로 대입할 수 없습니다.

추가 재현은 다음 명령으로 실행합니다. 임계값을 독립적으로 비교하기 위해 출력 안정화가 끝난 입력을 사용합니다. 결과는 합성 조건에서의 실제 코드 동작이며 실제 센서 성능/최적값을 뜻하지 않습니다.

기본 민감도와 일정한 기준에서 빛만 약 5.10 lx 증가해 유지되면 조명이 완화됩니다. 평소100%/하한1% 조건의 문턱 부근의 첫 완화 목표는98%이며 강한 점수4에서는1%이므로 문턱뿐 아니라 완화 폭도 실제 배치에 맞는지 확인해야 합니다. 소리만 변하면 RMS 증가 약 0.00778에서 조명과 팬이 같은 문턱에 진입합니다(팬 검토 격자 0.0001에서는 0.0078). 이전 팬 진입 폭은 약 0.0223이었으나 별도 점수와 문턱을 제거해 맞췄습니다. 이 값은 특정 합성 조건의 공학 값이며 임상 역치가 아닙니다.

학습은 AUTO의 평소 출력이 안정되고 가중 절대 변화 합이0.7 이하인 구간에서만 수락합니다. 수동/잠시 사용/안전 모드, 완화·복귀와 전환 중에는 갱신하지 않습니다. 외부100→40 lx 30초→100 lx에서 기준100 lx/복원 점수0이 유지됩니다. 100→104 lx는 점수1.1로 유지되며 완화·학습을 보류합니다. 100→102 lx는 학습해 최종점수0이 됩니다. 느린 증가의 학습은 유지하되 빠르고 큰 증가가 지속되면 자극으로 유지하며, 오래 지속됐다는 이유로 정상에 흡수하지 않습니다.

회복 확인2.5초는 낮은 변화가 이어지는지 확인한 뒤 점진 복귀를 시작하는 시연/제품 공학 값으로 유지합니다. 아이의 진정 시간이나 복귀 완료 시간은 아닙니다. 이후 사용자 평가, 연구 및 실제 센서·출력 로그로 확인 시간을 보완합니다. 최소 유지·센서 유효성·출력 안정화·점진 복귀가 추가되므로 실제 복귀는 더 오래 걸립니다.

처음부터 일정한 1000 lx/높은 상대 RMS로 켜진 경우에도 변화 점수는 0이 됩니다. 따라서 점수 0은 변화가 작다는 뜻이며 환경의 편안함을 확정하지 않습니다. 위 검증은 발견한 한계를 함께 기록하는 검토용이며, 68개 조건의 반복 제어 안정화 검증이 장기 환경 적응까지 통과했다는 의미는 아닙니다.
