# SensoryShield

SensoryShield는 nRF54LM20 DK 기반의 로컬 감각 환경 제어 펌웨어입니다. Zephyr RTOS와 C++17을 사용하며, 로컬 센서 처리, WS2812B LED 링 및 PWM 팬 제어, 영구 앱 설정, Thread IPv6 네트워크, 로컬 HTTP REST API를 포함합니다.

## 펌웨어

펌웨어는 NCS sysbuild 기준으로 빌드합니다. MCUboot, Matter factory data, SensoryShield 애플리케이션이 함께 빌드되고, 전체 플래시 때 같은 순서로 보드에 기록됩니다.

처음 빌드하거나 빌드 설정이 바뀐 경우:

```sh
./scripts/build.sh --pristine
./scripts/flash.sh
```

평소 증분 빌드와 앱만 빠르게 다시 올리는 경우:

```sh
./scripts/build.sh
./scripts/flash.sh --app-only
```

`./scripts/flash.sh`는 `mcuboot`, `matter_factory_data`, `SensoryShield` 도메인을 모두 플래시합니다. `./scripts/flash.sh --app-only`는 이미 MCUboot와 factory data가 설치되어 있다는 전제에서 SensoryShield 앱 도메인만 업데이트합니다.

VS Code 작업도 같은 스크립트를 호출하도록 구성되어 있습니다.

## 프론트엔드

```sh
cd frontend
npm install
npm run dev
npm run build
```

펌웨어 빌드는 프론트엔드 production 빌드를 실행하고, 생성된 HTML, JavaScript, CSS를 압축해 펌웨어 이미지에 포함합니다. 보드에서는 Thread 네트워크에 붙은 뒤 로그에 출력되는 LAN-routable IPv6 주소로 웹 UI를 제공합니다.

개발 서버는 5173 포트에서 실행됩니다. 실제 보드로 `/api` 요청을 프록시하려면 `frontend/.env`에 `API_TARGET=http://[보드 IPv6 주소]`를 설정하거나 `API_TARGET='http://[보드 IPv6 주소]' npm run dev`처럼 대상 주소를 지정합니다. 보드가 없으면 프론트엔드는 오프라인 미리보기 상태로 동작하고 장치 제어는 비활성화됩니다.

REST API는 `/api/status`, `/api/light`, `/api/fan`, `/api/mode`, `/api/profile`, `/api/diagnostics`, `/api/factory-reset`을 제공합니다. `/api/light`는 `power`, `brightness`, `cct`, `rgbMode`, `red`, `green`, `blue`를 받을 수 있습니다. Matter ColorControl은 Level, ColorTemperature, Hue/Saturation 명령을 지원합니다. factory reset 엔드포인트는 확인 요청이 있는 경우에만 동작합니다.

## 현재 하드웨어 매핑

- BH1750 I2C: SDA `P1.12`, SCL `P1.13`
- MP34DT01 PDM: CLK `P1.14`, DATA `P1.11`; 16 kHz mono, 100 ms window
- HC-SR501 PIR: `P1.10`
- WS2812B 12 LED ring: `DI` -> `P3.00` 출력 가능 GPIO 패드, `5V` -> 5 V 전원, `GND` -> 공통 GND, `DO` -> 다음 LED 체인 연결용 또는 미사용
- Fan PWM: `P3.02`

WS2812B `DI`는 보드의 출력 가능한 GPIO 패드에 연결합니다. 현재 펌웨어는 `P3.00`을 WS2812B 데이터 파형 출력으로 사용합니다.

WS2812B 조명은 밝기 디밍, RGB 색상, 백색 색온도 제어를 지원합니다.

Thread REST 접속에는 보더 라우터가 LAN으로 광고한 OMR IPv6 주소를 사용합니다. 링크 로컬, mesh-local, RLOC 주소는 일반 LAN 클라이언트에서 직접 접근할 수 없습니다.

### 처음 설정과 자동 학습

처음 설문조사는 빛 민감도, 소리 민감도, 자극 완화 시 사용할 색온도 세 질문입니다. 별도의 환경 측정·조명/팬 체험 단계는 없습니다. 민감도는 변화에 반응하는 크기에 반영하며 반응 시간을 직접 정하지 않습니다. 선택한 색온도는 조명을 낮출 때 사용할 목표입니다. 250/333/417 mired 프리셋은 제품 선택값이며 치료 기준이 아닙니다. 설정 화면에서 나중에 변경할 수 있습니다.

자동 학습은 평소 대비 밝기·소리 증가를 비교하기 위한 것입니다. 첫 유효 자료부터 임시 중앙값으로 점수를 계산하며, 각 채널에 수락한 새 표본 31개가 쌓이면 전체 창을 사용합니다. 알고리즘 주기 250 ms에서 모두 유효하고 출력이 안정적이면 약 8초입니다. 출력 전환·오류·중복 자료는 세지 않아 실제 시간은 길어질 수 있습니다. 이는 초기 통계 창의 준비이며 시간대별 개인화 완료나 임상적으로 검증한 적응 기간이 아닙니다. 재부팅 때에는 현재 환경으로 다시 시작합니다. `sensor.baselineReady`는 입력과 통계 창의 준비 상태로 정확도 백분율이 아닙니다.

화면에는 “평소 환경을 자동으로 학습하고, 빛과 소리 변화에 맞춰 조명과 팬을 조절해요.”라고 안내합니다. 점수는 주변 변화 지표이며 아이의 불편함을 확정하거나 진단하지 않습니다. 표시 범위는 `STIMULUS_MAX_SCORE = 4`, 문구 경계는 1.4·2.8입니다. 점수 계산식·가중치·기존 높은 입력의 학습 제외 조건은 유지합니다.

### 평소 출력과 자극 완화

저장 호환성을 위해 API 필드 이름 `preferredBrightness`, `preferredFanPercent`는 유지하되 설정 화면에서는 평소 조명 밝기와 평소 바람 세기로 설명합니다. 설문에서 두 값을 수집하지 않고 보호자가 설정에서 허용 범위 안으로 직접 조절합니다. 정상 조명의 색온도는 설정 범위의 선명한 쪽인 `minCCTMireds`입니다. `preferredCCTMireds`는 자극 완화 시 사용할 빛입니다. 색온도 선택이 평소 밝기·바람 세기를 덮어쓰지 않습니다.

자동 조명은 정상 → 자극 확인 → 완화 유지 → 회복 확인 → 점진 복귀 순서입니다. 유효하고 출력이 안정된 입력에서 점수 1.4 이상이 750 ms 지속되면 점수에 비례해 평소 밝기부터 최소 밝기까지 낮추고 선택한 색온도를 적용합니다. 완화 중 점수가 더 높아지면 추가로 낮출 수 있습니다. 최소 1,500 ms 유지한 후 점수 0.7 이하가 2,500 ms 지속되면 회복을 시작합니다. 회복은 유효하고 안정된 입력에서 500 ms마다 밝기를 2%p 올리며 색온도도 정상 쪽으로 복귀합니다. 회복 중 점수가 다시 높아지면 멈추고 완화를 유지합니다. 출력이 바뀌는 동안 입력 안정화를 기다리므로 실제 복귀는 더 오래 걸릴 수 있습니다. 센서 오류를 조용함으로 취급해 밝기를 올리지 않습니다.

위 점수·시간·변화 폭은 반복 제어를 막기 위한 초기 공학 설정이며 임상 기준이나 논문이 검증한 값이 아닙니다. 실제 센서 지연·출력 반응에 맞춰 검증하고 조정해야 합니다. MANUAL/OVERRIDE와 직접 설정한 계속 유지 기능을 우선하며, 모드 변경 때 조명 완화 상태만 다시 시작하고 학습 기준은 보존합니다. PIR 종료 조건은 기존대로 유지합니다.

팬은 기존 소음 판단·진입·회복 임계값을 유지합니다. 정상 출력은 `preferredFanPercent`, 조용 출력은 기존 20%와 정상 출력 중 작은 값이며 상한을 적용합니다. 정상 출력 0%이면 자동 팬을 끕니다. 팬 자체 출력 전환의 소음 자료는 학습과 상태 확인 시간에 사용하지 않습니다. 소음·환기 담당자에게 이 입력 처리 변경을 공유해야 합니다.

### 자체 출력 변화와 센서 입력의 분리

센서 자료에는 읽을 당시의 실제 조명 밝기·색온도·RGB·전원, 팬 속도·전원과 시각을 함께 담습니다. Matter에서 변경한 실제 출력도 포함합니다. `OutputAwareInputs`는 빛과 소리를 별도로 처리합니다. 목표 전환·실제 출력 변경·읽는 중 출력 변경·오래된 자료가 있으면 해당 채널 비교값을 유지하고 학습을 보류합니다. 출력이 안정된 뒤 최소 500 ms를 확인해 새 관측 지점을 잡고, 같은 출력에서 발생한 센서 변화만 비교값에 누적합니다. 처음 관측한 출력으로 돌아오면 원시값으로 다시 비교할 수 있습니다. 화면에 표시하는 주변 밝기·소리 원시값은 이 비교값으로 덮어쓰지 않습니다.

이 기본 방식은 우리 명령으로 발생한 센서값 점프를 제외하는 추정입니다. 수동 모드를 전부 학습에서 빼지 않고 같은 출력에서 관측되는 실제 외부 변화는 계속 반영합니다. 출력 전환과 동시에 발생한 외부 변화는 보정 없이 구분할 수 없으며 그 구간의 변화를 놓칠 수 있습니다. 실제 광학 영향이나 팬 소음을 소프트웨어만으로 정확히 확정한 것은 아닙니다.

`src/common/algorithm/light_sensor_calibration.h`에 설치별 조도 보정 구조를 마련했습니다. 기본값은 비활성화입니다. LED를 끈 상태의 주변 조도를 빼서, 100% 출력의 250/333/454 mired에서 센서에 더해지는 lux 세 값을 측정합니다. 밝기에 비례하고 색온도 사이를 선형 보간하는 근사 모델이므로 25/50/75/100%와 중간 색온도에서 오차를 먼저 검증해야 합니다. 결과가 적합할 때 `InstallationLightCalibration`에 실측값을 넣고 다시 빌드합니다. 예시 시뮬레이션 계수를 실측값으로 넣지 않습니다. 보정이 활성화된 백색 조명에서는 같은 읽기 동안 출력이 일관된 경우 전환 중 외부 변화도 비교할 수 있습니다. RGB와 모델 범위 밖은 기본 추정으로 돌아갑니다. 마이크·팬 소음에 대한 실측 보정 모델은 아직 없습니다.

프로필 저장 포맷 v7과 v4/v5/v6 마이그레이션은 유지합니다. 기존 초기 관측 기록은 저장 호환성을 위해 보존하지만, 출력 상태 정보가 없어 자동 시작·재부팅 학습의 고정 시작값으로 사용하지 않습니다. `useMeasuredEnvironment: true`인 프로필 저장은 거절합니다. 기존 `/api/environment-measurement` 수집 엔드포인트는 진단용 호환 코드로 남아 있으며 사용자 설문 흐름에서 호출하지 않습니다. 공장 초기화는 기존 설정과 기록을 지웁니다. WS2812B 백색 혼합의 발광색과 센서 배치는 실제 보드에서 확인해야 합니다.

### 아이 화면의 불편 요청

아이 화면은 `너무 밝아요`, `너무 어두워요`, `너무 시끄러워요`, `너무 조용해요` 네 요청만 제공합니다. `지금 좋아요`와 시간 선택은 제거합니다. 버튼을 누르면 최신 기기 출력과 보호자 설정을 다시 읽어 실제 REST 제어 명령을 보냅니다. 밝기 요청은 현재 밝기에서 10%p 낮추거나 높이고 허용 범위를 적용합니다. 소음 요청은 조명을 낮추고 팬을 20%p 줄입니다. 팬의 최소 구동값 18%보다 낮아질 때에는 끕니다. 조용함 요청은 조명은 유지하고 팬을 켜거나 20%p 올리며 보호자의 최대 세기를 넘지 않습니다. 이는 팬 구동 요청이며 백색소음이나 치료 효과를 보장하는 기능이 아닙니다. 조명이 이미 꺼져 있을 때 밝기·소음 완화 요청이 조명을 켜지 않으며, 감소 요청이 기존 낮은 출력을 높이지 않습니다. 최대 세기가 0인 팬은 아이 요청으로 켜지지 않습니다.

출력이 바뀐 요청은 기존 기본 15분 OVERRIDE로 유지한 뒤 AUTO로 돌아갑니다. 아이가 시간을 선택하지 않으며 보호자 화면에서는 기존 수동·잠시 사용·자동 전환을 사용할 수 있습니다. 조정 폭과 기본 복귀 시간은 제품 동작 값으로 임상 기준이 아닙니다. 더 바꿀 수 없으면 한계를 안내하며, 연결 실패·부분 적용·자동 복귀 설정 실패를 성공으로 표시하지 않습니다. PIR 종료 조건은 유지합니다. 아이 요청으로 생기는 자체 출력 변화에도 위 입력 분리 규칙을 적용합니다.

### 하드웨어 없는 알고리즘 검증

```sh
bash scripts/test-host.sh
node tests/ui/mock-api.test.mjs
node tests/ui/child-control.test.mjs
bash scripts/simulate-environment.sh /tmp/sensoryshield-environment-simulation
python3 scripts/analyze-environment.py /tmp/sensoryshield-environment-simulation --check
# matplotlib이 설치되어 있다면 --plot을 추가해 비교 그래프도 생성할 수 있습니다.
```

호스트 시험은 실제 C++ 점수 계산·조명·팬·출력 인식·설정 저장 코드를 실행합니다. 조명과 팬의 합성 센서 간섭을 함께 적용해 정상→외부 변화→완화→외부 변화 제거→정상 복귀를 확인합니다. 유효/중복/오류 입력, 수동 출력 변경, 보정 사용과 보정 불가능한 동시 외부 변화도 시험합니다. 모의 API는 화면과 REST 요청 흐름을 확인하는 고정 자료이며 실제 알고리즘 예측을 대체하지 않습니다.

조명 시뮬레이션은 실제 C++ 점수 계산·출력 인식·조명 제어를 실행합니다. 센서 수집 200 ms, 알고리즘 250 ms, 밝기 전환 2%p/25 ms와 색온도 전환 8 mired/25 ms를 별도 일정으로 모델링합니다. 각 실행은 합성 평소 표본 31개로 시작해 5분 실행합니다. 정상 밝기 100%·60%, LED 센서 기여 0~2 lx/%p, 센서 위상 0·100 ms, 외부 변화 유지/제거, 수동→자동, 느린/빠른 외부 변화를 포함한 56개 조건입니다. `learn`은 갱신하는 계산기, `freeze`는 시험용 초기 기준 고정 비교군이며 제품 기능이 아닙니다.

원시 lux에는 자체 조명 빛이 포함되고, `baseline_lux`는 출력 영향을 제외한 비교 좌표의 기준입니다. 둘이 같아야 하는 것은 아닙니다. `summary.csv`·`summary.json`에는 마지막 60초의 목표 변경과 출력 방향 반전, 기준·점수·범위를 기록합니다. `--check`는 모든 조건의 마지막 60초가 안정적이고 수동 복귀 및 변화 제거 조건이 정상 밝기로 돌아왔는지 검증합니다.
