# 소음과 팬 고도화 인계

담당 브랜치: `feat/jiyun-sound-fan`. 기존 SensorSnapshot, ControlTarget, AppConfig 및 REST API 필드를 유지한다. 새로운 팬 정책은 `src/common/algorithm/sound_fan.h`에 분리했으며 공통 RollingBaseline, 조명 계산식, 재실 timeout, 장치 드라이버는 변경하지 않았다.

## 자동 팬 정책

| 조건 | 목표 동작 |
| --- | --- |
| 기준선 준비 전 | 유효한 입력이면 18%로 시작 |
| 정상 환경 | 30% 이하, 프로필 상한 준수 |
| 순간 소음 | 1.5초 연속 조건을 만족하지 않으면 조용한 모드로 전환하지 않음 |
| 지속 소음 | 상승 편차 × soundWeight가 3 이상으로 1.5초 지속되면 18%로 감속 |
| 회복 | 가중 편차가 1.5 이하로 3초 지속되면 정상 목표로 복귀 |
| 마이크 오류, 범위 초과, NaN, 1초 넘은 입력 | 현재 출력에서 증가시키지 않고 최대 18%로 제한. 정지 중이면 유지 |
| 재실 없음 또는 PIR 오류 | 즉시 팬 목표 0% |
| 상한 0~17% | 팬 목표 0%. 드라이버의 최소 PWM 18%보다 낮은 값은 구동하지 않음 |

시작은 최소 구동 목표 18%, 정상 변화는 알고리즘 주기(250ms)당 최대 2%p다. 안전 정지, 상한 감소 및 입력 실패는 즉시 제한한다. 샘플 시각이 같으면 기준선이나 지속시간 상태를 중복 갱신하지 않는다. 시간 비교는 uint32_t 순환을 고려한다.

팬 기준선에는 RMS 에너지를 사용한다. 높은 양의 편차 구간을 학습하지 않으며 peak/delta가 순간음 조건을 만족할 때도 학습을 보류한다. 밝기가 팬 속도를 직접 올리지 않도록 합산 감각 점수와 팬 정책을 분리했다. 기존 화면의 합산 sensoryScore와 조명 계산은 그대로이므로 해당 점수는 팬 모드의 직접적인 설명값이 아니다.

수치는 실측 전 임시값이다. 첫 기준선은 초기 환경을 정상으로 학습하므로 처음부터 시끄러운 공간의 절대 소음 판정은 지원하지 않는다. 소리 수치는 dB가 아니고 팬 속도는 측정 풍량이 아닌 명령 비율이다.

## UI 변경

팬 슬라이더는 선택값을 유지하고 명시적인 속도 적용 버튼으로 전송한다. 상태 polling은 사용자의 미적용 선택값을 덮어쓰지 않는다. 명령 처리 중 조작을 막고 성공 전송과 실제 수신 상태를 구분한다. 실제 펌웨어처럼 팬 수동 명령은 MANUAL로 전환한다.

팬 상한을 프로필에서 확인한 뒤 시작/속도 적용을 허용한다. 조회 실패 시 재시도 버튼이 있다. 소리 값은 소수점 한 자리 상대 입력으로 표시하고 측정 실패를 구분한다. 통신 실패는 마지막 수신값을 보존하면서 제어를 비활성화하고 마지막 수신 시각을 표시한다. polling은 요청 완료 후 다음 요청을 예약한다.

## 개발 화면 실행

PowerShell에서 저장소 폴더를 연 뒤:

```powershell
cd frontend
npm ci
npm run dev:mock
```

`http://localhost:5173`을 연다. 상단 Mock 표시의 시나리오 변경 링크는 `/__mock`으로 이동한다. normal, noise, impulse, mic-error, vacant, offline, command-error를 선택할 수 있다. 시나리오 변경은 AUTO로 초기화한다.

Mock은 화면 시험용 고정 응답이며 C++ 알고리즘의 실행 결과가 아니다. Mock 미들웨어는 개발 서버의 mock 모드에서만 사용하며 production bundle에는 포함되지 않는다. 실제 보드 연결은 기존 `npm run dev` 및 `http://192.0.2.1/` 흐름을 사용한다.

## 검증

- C++17 host 시나리오 시험 통과: 정상/순간음/지속음/회복, 반복 경계, 상한, 무재실/PIR 오류, 마이크 오류/오래된 값/NaN/음수, 민감도 0, 중복 샘플, 시간 순환.
- AddressSanitizer 및 UndefinedBehaviorSanitizer 시험 통과. 실행 환경의 /proc 제한 때문에 누수 검사는 비활성화했다.
- Mock API 시나리오 시험 통과.
- TypeScript 검사와 Vite production build 통과.
- 브라우저 E2E 시험 스크립트는 준비했으나 이 실행 환경에서 Chromium 다운로드가 실패하여 미실행. 화면 외관, 모바일 및 실제 슬라이더 조작은 확인 필요.
- Nordic NCS SDK/보드가 없으므로 전체 펌웨어 빌드 및 실물 동작은 미검증.

Host 시험(g++가 설치된 환경):

```sh
g++ -std=c++17 -Wall -Wextra -Werror -Isrc tests/host/sound_fan_test.cpp src/common/algorithm/baseline.cpp -o sound-fan-test
./sound-fan-test
node tests/ui/mock-api.test.mjs
```

브라우저 시험은 Playwright와 Chromium이 있는 환경에서 Mock 개발 서버를 먼저 실행한 후 `node tests/ui/fan-smoke.cjs`를 실행한다. 이 저장소의 기본 npm 의존성에는 Playwright를 추가하지 않았다.

## 한상문과 실물 통합 시 확인

1. 실제 조용한/순간음/지속음 및 팬 OFF/18%/30%/상한별 RMS/peak/delta 로그. 팬 자체 소음이 자동 감속/회복 반복을 유발하는지 확인한다.
2. 최소 구동 PWM과 시동 출력. 기존 드라이버는 낮은 비율을 18%로 올리고 시동 때 350ms간 100%를 출력하므로, 프로필 상한은 현재 구조에서 물리 출력의 절대 상한을 보장하지 않는다.
3. System의 AUTO ApplyTarget과 ActuatorRampWork가 각각 출력을 적용하는 경로. 컨트롤러가 목표값을 제한해도 물리 출력/명령 순서가 안정적인지 확인한다.
4. MANUAL/OVERRIDE 복귀 시 이전 AUTO 목표와 실제 수동 출력의 차이. 부드러운 전환을 위해 필요하면 System과 함께 컨트롤러의 적용값 동기화를 추가한다.
5. 센서 실패 때 SAFE 전환 여부 및 PIR 유효성 정책을 통합 기준으로 확정한다.
6. Override는 기존 고정 15분과 수동 명령의 MANUAL 전환 동작을 유지했다. 5/10/30분 선택과 남은 시간 표시는 API 확장이 필요하므로 이번 변경에 포함하지 않았다.


## 소음과 팬 UI 후속 개선

팬 카드의 현재 속도는 큰 숫자로, 적용할 속도는 별도 선택 영역으로 구분했다. 선택 영역에는 적용 전 상태와 최소/상한 값, 전체 너비 적용 버튼을 표시한다. range track은 18~설정 상한 범위에 맞게 채워져 슬라이더 손잡이와 진행 표시가 일치한다. 모바일에서는 현재 상태/전원 버튼과 선택 영역이 겹치지 않도록 전용 CSS를 사용한다.

소리 입력은 수치와 작은 입력 막대를 함께 표시하며 상대 입력값임을 명시한다. 정상/높음 등 임의의 소음 등급은 붙이지 않았다. 센서 오류와 비정상 수치는 측정 불가로 표시한다. 설정에서는 소리 민감도 0%의 의미와 팬 한도 0%/18% 미만 정책을 입력 옆에 설명한다.

공통 global.css, 조명 카드, API 및 알고리즘은 이번 UI 후속 변경에서 수정하지 않았다. 추가 CSS는 fan-control.css와 sound-metric.css로 분리했다. 기존 브라우저 시험의 현재 속도 확인 부분은 변경된 마크업에 맞춰 갱신했다.

이전 UI 버전은 사용자가 Windows Chrome에서 속도 선택값 유지/적용, 정지/재시작/자동 복귀, 소음/마이크 오류/무재실/정상 복귀, 연결 끊김/복구, 명령 실패/재시도, 팬 상한 40%/0%/80% 및 모바일 표시가 정상임을 확인했다. 후속 UI 버전은 TypeScript와 production build를 검증했으며 실제 브라우저 재확인은 아직 필요하다.

## 작동 방식 안내와 최종 작업 구분

ModeSwitch에 현재 모드의 동작 설명을 추가했다. AUTO는 센서 기반 제어, MANUAL은 저장된 수동 설정 유지, OVERRIDE는 저장된 수동 설정을 15분간 사용한 뒤 AUTO로 복귀하는 기존 펌웨어 동작을 안내한다. OVERRIDE 중 조명/팬 명령은 MANUAL로 전환되므로 자동 복귀가 해제되는 점도 표시한다. API에 만료 시각이 없으므로 남은 시간은 표시하지 않는다.

모드 요청의 ok:false를 실패로 처리하고 중복 전송 및 현재 모드 재선택을 막았다. 변경 요청 성공과 기기에서 수신된 모드는 구분하며, 연결이 없으면 모드 안내 대신 연결 안내를 표시한다. 공통 모드 UI 파일만 수정했고 모드 API, 펌웨어, 조명 제어 계산은 유지한다.

지윤의 소프트웨어 구현은 소음 기반 자동 팬 정책, 수동 팬 제어/상한 확인/실패 복구, 소리 입력 및 팬 UI, 작동 방식 안내까지 완료했다. 추가 기능은 팀이 요구사항을 정한 뒤 진행한다. 남은 실제 통합은 다음과 같다.

- 윤서: 공통 파일 변경 범위 확인 후 조명·재실 작업과 브랜치 병합. SettingsPage, EnvironmentSummary, ModeSwitch 및 연결 상태 관련 파일에 동시 변경이 있으면 함께 확인한다.
- 한상문: NCS 전체 펌웨어 빌드, 보드 연결, 마이크/팬 실측, 최소 구동·시동 출력과 AUTO 적용 경로 확인.
- 지윤: 실측값을 전달받은 뒤 sound_fan.h의 소음 진입/회복 기준과 지속시간을 조정하고 팬 자체 소음에 의한 반복 감속 여부 확인. 이 단계는 아직 수행하지 않았다.

기능 동작은 기존 UI 버전에서 사용자 확인을 받았으며 최신 UI 외관과 모드 안내의 브라우저 확인은 별도로 남아 있다. 전체 프로젝트의 실물 동작 완료를 의미하지 않는다.
