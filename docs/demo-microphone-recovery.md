# 시연 입력 복구와 시작 화면 (2026-10-15)

## 확인한 문제

실제 보드는 AUTO, 재실 자동 종료 꺼짐, 조명100%/289mired/팬20%를 보고했고,
팬 PWM은 정상인데 전체 입력 안정 상태가 계속 false였다. 소리 응답은0.000으로 반복됐다.
온보딩 완료 기록과 완화 빛454mired는 이미 저장돼 있었다.

`Mic::CaptureLoop`는 `dmic_read(..., SYS_FOREVER_MS)`를 사용했다.
현재 NCS3.4.0의 `dmic_nrfx_pdm.c`는 RX큐 또는 메모리 오류 때 PDM을 정지할 수 있다.
앱에는 읽기 시간 제한과 재시작이 없어서, 수집 중단 후 다음 창을 영원히 기다릴 수 있었다.
`LatestFeatures`도 마지막 valid값을 그대로 반환해 화면의 정상 표시와
제어기의 최근1초 표본 검사가 달라졌다. 오래된 valid표본을 넣으면 위 출력 정체를 재현했다.
실물의 최초 정지 계기(큐 포화인지 다른 드라이버 오류인지)는 당시 로그가 없어 미확정이다.

## 수정

- 읽기를500ms로 제한한다. 실패·잘못된 버퍼는 무효로 표시하고 STOP 후100ms 대기,
  오래된 큐 버퍼 반환, 재설정 및 START 순서로 복구한다. 실패한 재시작도 대기 후 재시도한다.
- 1초 이상 된 표본은 화면에도 무효로 전달한다. 새 PCM 창을 받아야 정상으로 복귀한다.
- `/api/diagnostics.microphone`에 표본 수, 마지막 수신 경과, 재시작 횟수, 오류,
  fresh/recovering을 제공한다. 작은 RMS가0.000으로 반올림되지 않도록 상태API 정밀도를6자리로 높였다.
- 웹을 새로 열거나 새로고침하면 저장된 선택을 불러온 뒤 세 단계 온보딩을 먼저 표시한다.
  불러오기 실패 시 대시보드로 넘어가지 않는다. 저장 및 AUTO 요청이 성공해야 대시보드가 나온다.
- 시연 완화 팬 기본값은0%. v9이하의 저장값 중 이전 기본값20%도0%로 이관한다.
  다른 사용자 설정, 재실 선택, 유지 시간, Matter 등록은 보존한다. v10에서 새로 지정한20%는 보존한다.
- 완화 색온도는 기존 선택값을 사용한다. 팬 정지와 선택 색온도 도달 및 복귀를 회귀 시험으로 확인했다.

## 유지한 시연 설정

평소 밝기/팬100%, 조명 하한30%, 진입1.4점/3초, 목표 전환5초,
도달 후 최소 유지5초, 복귀 확인0.7점/3초, 복귀 목표5초,
아이 요청 도달 후 유지5초, 재실 유지30초/자동 종료 기본 꺼짐.
마이크16kHz/100ms창 및 센서200ms/알고리즘250ms 주기는 유지한다.

## 검증

`bash scripts/test-host.sh`는 실제 마이크 처리 코드의 중단·버퍼 반환·재시작·재실패·새 PCM 수신과
실제 제어기의 오래된 입력 차단→새 입력 회복→세 색온도 완화→팬0%→복귀를 검증한다.
`node tests/ui/mock-api.test.mjs`, `node tests/ui/child-control.test.mjs`와
`tests/ui/onboarding-smoke.cjs`는 설정 보존, 새 브라우저의 온보딩, 로드 실패/재시도,
저장 후 AUTO, 소음 수치 및 복구 표시를 검증한다.
브라우저 시험은5174포트의 mock서버를 사용하며 실제 보드를 조작하지 않는다.

펌웨어 업데이트 후 실물에서 확인할 항목:

1. 새 웹에서 온보딩을 완료하고 AUTO 확인. 팬 완화 목표0%와 선택한 빛을 설정에서 확인.
2. 기기 상태의 마이크 표본 수가 계속 증가하고 마지막 수신 경과가 짧게 유지되는지 확인.
3. 빛 또는 소리 입력을3초 이상 유지해 조명30%/선택한 빛/팬OFF 도달 확인.
4. 입력 제거 후 최소 유지·낮은 점수 확인·점진 복귀와 팬 재기동 확인.
5. 오류가 발생하면 마이크 복구 횟수와 마지막 오류를 기록한다. 호스트 시험 통과는 실물 측정 검증을 대신하지 않는다.
